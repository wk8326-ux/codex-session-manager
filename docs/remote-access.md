# 手机远程访问与会话同步

## 运行结构

Codex 会话管理使用一个独立进程，同时提供本机管理端和手机 PWA：

```text
127.0.0.1:8767
  本机管理：会话监控、远程同步目录、配对与设备撤销

0.0.0.0:8766
  远程访问：PWA、配对领取和已同步会话

Codex App Server / stdio
  thread/read、thread/resume、turn/start、turn/steer、事件通知
```

`python app.py` 或 `start-session-manager.bat` 会同时启动 8767、8766、监控调度器、FRP 和 Codex App Server。它与 Local Project Console 没有进程依赖；关闭会话管理不会影响项目控制台，反之亦然。

## 网络选择

### 同一局域网

电脑和手机连接同一可信网络时，可使用：

```text
http://<电脑局域网 IP>:8766
```

如果手机无法打开，请确认 Windows 防火墙允许 Python 在专用网络监听 TCP 8766，并确认无线路由器没有启用客户端隔离。

### 跨网络

推荐通过自建 VPS、FRP 和 Nginx 提供稳定的 HTTPS 地址；也可以使用 Tailscale、ZeroTier 或其他可信隧道。把手机实际能够访问的根地址填入配对页面，例如：

```text
https://console.example.ts.net
```

自建方案和控制台自动管理 `frpc` 的步骤见 [使用自建 VPS 和 FRP 远程访问](frp-remote-access.md)。

二维码中的一次性密钥位于 URL fragment，即 `#secret=...`，浏览器不会在 HTTP 请求中把 fragment 发送给服务器。不要在聊天、截图或仓库中公开完整配对链接。

## 权限边界

8766 不提供以下能力：

- 新增、编辑或删除监控渠道
- 读取兼容 API Key
- 修改会话监控与桌面桥接设置
- 访问未加入远程同步目录的 Codex 会话

会话内容会过滤本地命令、工作目录、命令输出、文件路径、工具参数和隐藏推理正文；用户消息、助手消息和公开的过程摘要可以显示。

## 选择同步会话

在电脑端打开“远程会话 > 会话”，点击“管理同步”，然后从本机 Codex 会话列表中选择需要在手机端查看的会话。同步名称可以在加入前修改。

远程同步目录与会话监控目录相互独立：

- 加入远程同步不会启用 API 探测、异常判断或自动续跑。
- 加入会话监控不会自动把该会话暴露给移动设备。
- 移除远程同步只撤销远程访问，不删除原 Codex 会话，也不修改监控配置。
- 8766 端口只能列出并访问用户明确加入远程同步目录的会话。

## 同会话消息发送

手机发送消息时，服务端先读取指定 `threadId` 的最新状态：

```text
最新 turn = inProgress
  -> turn/steer(threadId, expectedTurnId, input)

没有运行中的 turn
  -> thread/resume(threadId)
  -> turn/start(threadId, input)
```

服务端不会创建替代 thread，也不会自动 fork。`turn/steer` 使用 `expectedTurnId` 作为并发前置条件；如果状态在读取和发送之间发生变化，发送会明确失败并交给用户重试。超时或连接中断造成的“不确定结果”不会自动重发。

## 手机远程审批

由手机 PWA 发送并通过会话管理 App Server 执行的任务，可以在同一个 PWA 中处理后续授权请求。页面会把会话状态切换为“等待授权”，并显示命令、文件修改原因或请求扩展的权限：

- **允许一次**：仅批准当前请求。
- **本会话允许**：当 Codex App Server 提供该选项时，在当前会话范围内批准。
- **拒绝**：拒绝当前请求，任务可能因此停止或改用其他方案。

授权请求只会暴露给已经加入远程同步目录的会话。两分钟内没有处理、会话被移出同步目录或控制台关闭时，系统会自动拒绝。审批审计记录保存在本地 `watchdog.db`，只记录会话、请求类型、决定、设备和时间，不保存命令正文。

当全局续跑操作已开启时，“会话监控”中的“允许该会话无人值守执行”优先于手机手动审批：启用后，控制台拥有的命令执行和文件修改请求会按既有策略自动批准，不再进入手机待审批列表。权限扩展仍要求显式处理。

该能力不能接管由 Codex Desktop 自己的独立 App Server 发起、且已经在桌面端等待的审批请求。要使用手机审批，任务需要由 PWA 或会话管理这条 App Server 链路启动或续跑。

## 更新机制

会话管理把 App Server 通知转换为只包含以下字段的事件：

- 递增序号
- 事件方法
- 已加入远程同步目录的 `threadId`
- `turnId`
- `itemId` 和活动类型
- 安全状态字段
- UTC 时间

手机使用最长 25 秒的长轮询读取事件。收到当前会话的相关事件后会立即从 SessionProjection 获取脱敏后的最新内容。考虑到会话管理 App Server 与 Codex Desktop 并非同一个事件源，页面保留低频校准：运行中的会话约每 2.5 秒一次，空闲会话约每 8 秒一次，浏览器进入后台后约每 30 秒一次；会话目录状态约每 45 秒校准。相同会话的并发读取会在服务端合并。

消息区只读取最近 6 个轮次并保持固定高度。最近快照会写入浏览器 IndexedDB，重新打开或切回会话时先显示缓存，再后台校准；API 响应和设备令牌不会写入 Service Worker 缓存。新活动默认自动跟随到底部；用户向上滚动查看历史时会暂停跟随，并显示“回到最新”。运行状态优先依据最新轮次判断，避免 App Server 的 `notLoaded` 状态覆盖已经完成或正在运行的真实轮次状态。

事件流不会直接传输消息 delta、命令输出、文件路径或工具参数。页面显示的工具调用、文件变更数量、过程摘要和消息正文均来自重新读取后的脱敏会话快照。

## PWA

Service Worker 只缓存 HTML、CSS、JavaScript、图标和二维码库，不拦截或缓存 `/api/` 响应。认证令牌保存在配对设备浏览器的本地存储中。

除 `localhost` 外，浏览器通常只允许在 HTTPS 安全上下文安装 PWA 和启用 Service Worker。局域网 HTTP 仍可作为普通网页使用，但不保证出现“安装到主屏幕”入口。

## 设备丢失或授权异常

在电脑端打开“远程会话 > 配对设备”，撤销对应设备。撤销立即使该设备令牌失效，不影响其他设备。

如果浏览器清除了站点数据，需要重新生成二维码配对。二维码过期、重复领取或密钥错误时，服务端只返回统一失败信息，不泄露具体失败原因。
