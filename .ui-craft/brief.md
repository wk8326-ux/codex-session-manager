## 1. Product purpose

监控用户指定的 Codex 会话与 API 渠道，并通过移动端安全查看、续跑和人工控制会话。

## 2. Primary user

需要长时间运行 Codex 任务、在离开电脑时仍要掌握进度并处理异常的个人开发者。

## 3. Principles

1. **先看会话状态，再看配置。** 运行、完成、中断和等待审批必须一眼可分辨。
2. **自动恢复要可解释。** 每次静默、重试、续跑和失败都必须保留明确原因与时间。
3. **远程访问默认最小权限。** 只有用户显式登记的会话可以出现在 PWA。
4. **移动端是主界面之一。** 配对、会话切换、输入和审批必须适合单手使用与弱网络。

## 4. Success metric

用户打开页面后立即识别重点会话状态，并能在手机端可靠查看回复、发消息或处理审批。

## 5. Out of scope

- 不启动或管理普通开发项目
- 不读取未登记的 Codex 会话作为监控目录
- 不承诺 Codex Desktop GUI 实时刷新外部 App Server 写入
- 不提供多用户云端账户系统

## 6. Learned constraints

- **2026-08-21** — 桌面管理端只显示“功能总览、监控与续跑、远程会话”三个入口；Local Project Console 只通过普通项目记录启动本程序。*原因：两个仓库、进程和数据职责必须完全独立。*
- **2026-08-05** — 远程会话使用独立同步目录，不复用会话监控目录；桌面端通过紧凑管理弹窗从本机 Codex 选择和移除同步会话，手机端只读取用户明确授权的同步目录。消息视窗固定高度、内部滚动并默认聚焦最新消息，配对信息只出现在“配对设备”标签。*原因：远程查看/发送与 API 监控/自动续跑是不同权限边界，二者不能互相隐式启用。*
- **2026-08-05** — 远程会话必须持续呈现真实运行状态、当前活动与最近同步时间，不能退化成依赖手动刷新的静态快照；新内容默认跟随到底部，用户向上阅读历史时暂停跟随并提供“回到最新”。*原因：运行中的 Codex 任务需要持续反馈，同时不能打断用户阅读旧内容。*
- **2026-08-05** — 运行中的远程会话必须有持续、明确且固定可见的进行态动画；长消息按标题、段落、列表和代码等语义排版，不能直接显示难读的原始 Markdown。*原因：用户需要在等待时确认任务仍在推进，并能长时间阅读同步记录。*
- **2026-08-21** - Codex 会话管理的桌面页面复用同一侧栏；远程 PWA 保持独立移动客户端布局。页面切换只改变当前导航项，主题控件不发生空间跳变。*原因：管理端需要稳定导航，手机端则不应继承桌面侧栏。*
- **2026-08-06** - 手机 PMA 是远程会话的一级使用界面，不是桌面布局的缩小版；配对属于可恢复、可持久化的配置流程，完成后应直接进入会话，只有服务端明确返回授权失效才重新配对。短暂网络波动不得立即显示断开或把用户送回配对页。*原因：移动网络天然会抖动，连接状态与设备授权是两套独立状态，不能互相覆盖。*
- **2026-08-07** - 远程会话 PWA 是独立的移动优先对话客户端，项目工作台只保留入口；会话列表使用覆盖式抽屉，切换时不得推动或重排顶部会话标题、消息区和底部输入框。*原因：手机 PWA 不是桌面工作台的缩小版，选择会话不能让核心输入区域移出屏幕。*
- **2026-08-08** - 桌面端远程会话侧栏只改变自身可见性与主内容起点，不得重置、覆盖或停用当前会话工作区；会话状态必须同时使用图标和文字，运行态使用持续旋转指示。*原因：侧栏属于导航工具，展开和收起不能中断阅读、输入或会话状态，状态也不能只依赖颜色表达。*
- **2026-08-08** - 远程会话列表必须在用户点开会话前就根据真实最新 turn 显示完成、运行、失败或中断状态；状态详情暂时不可读时显示“状态未知”，不得猜测为“已停止”。*原因：点击行为只能切换内容，不能成为纠正状态的隐式数据加载步骤。*
- **2026-08-08** - 粘贴图片、页面截图和文件选择必须作为同一消息输入流程的一等入口，并共用附件预览与发送状态；Markdown 表格必须渲染为可横向滚动的语义表格，不显示原始管道文本。*原因：远程排查依赖真实界面截图，结构化回复也需要在手机窄屏上保持可读和可访问。*
- **2026-08-08** - 本机管理端截图使用独立安装的开源 Flameshot 自由框选引擎，允许跨出浏览器选择任意屏幕区域；配对的远程设备不得反向触发电脑屏幕截图，只保留浏览器截图作为非本机兼容方式。*原因：自由截图应使用成熟的桌面截图能力，同时主机屏幕属于明确的本地权限边界。*
- **2026-08-11** - 远程会话发送消息必须在网络请求开始前立即出现在对话区，并持续显示“正在送达、已送达、发送失败”之一；请求未结束时禁止重复提交，失败后恢复输入内容。*原因：发送后的空白等待会让用户误判为未发送并重复操作，即时且可恢复的反馈是远程对话的基本可靠性信号。*
- **2026-08-12** - 远程会话的详情同步不能依赖单一事件长轮询；流式事件高频到达时不得反复推迟实际内容读取，移动端还必须有独立心跳补拉。控制台与 FRP 必须保持单实例。*原因：消息送达与回复展示是两段链路，事件风暴或重复后台实例会造成电脑已有回复而 PWA 停留在旧快照。*
