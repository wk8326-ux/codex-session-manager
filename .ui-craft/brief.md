## 1. Product purpose

集中登记、启动、关闭和访问这台 Windows 电脑上的本地开发项目与常驻网页入口。

## 2. Primary user

同时维护多个小项目的个人开发者，在桌面浏览器上每天多次确认服务状态并快速进入工作界面。

## 3. Principles

1. **先看状态，再看设置。** 首屏必须先回答哪些服务正在运行，配置细节只能作为辅助信息。
2. **一次点击执行，两个信号确认。** 高频启动与关闭操作保持直接，运行判断同时呈现端口或进程证据。
3. **让项目可以横向比较。** 名称、入口、命令、状态和操作必须固定在稳定的扫描位置。
4. **本地工具就该像本地工具。** 界面安静、快速、可靠，不使用营销页构图或装饰性视觉。

## 4. Success metric

用户在打开页面后 10 秒内识别所有项目状态，并能用一次点击启动、关闭或打开目标项目。

## 5. Out of scope

- 不编排项目之间的启动依赖关系
- 不保存长期运行指标或历史趋势
- 不管理远程服务器进程
- 不提供多用户权限和云端同步

## 6. Learned constraints

- **2026-07-27** — 不同项目类型使用固定宽度的操作列；主操作共用同一条左对齐线，编辑和删除等辅助工具固定靠右。*原因：项目行需要横向比较，按钮不能因为数量不同而改变网格轨道起点。*
- **2026-07-28** — “网页入口”是项目类型，不是运行状态；远程网页必须根据 URL 可达性显示“在线”或“离线”，本地项目则根据进程或端口显示“运行中”或“已关闭”。*原因：打开入口与健康监控是两种不同职责，状态列必须呈现真实的检测结果。*
- **2026-08-05** — 三个工作区的左侧导航只保留“项目控制台、会话监控、远程会话”三个平级入口，不显示分类标题或项目状态子筛选。*原因：一级导航承担跨工作区定位，项目状态已经在主内容区完整呈现，重复筛选会增加视觉噪声。*
- **2026-08-05** — 远程会话使用独立同步目录，不复用会话监控目录；桌面端通过紧凑管理弹窗从本机 Codex 选择和移除同步会话，手机端只读取用户明确授权的同步目录。消息视窗固定高度、内部滚动并默认聚焦最新消息，配对信息只出现在“配对设备”标签。*原因：远程查看/发送与 API 监控/自动续跑是不同权限边界，二者不能互相隐式启用。*
- **2026-08-05** — 远程会话必须持续呈现真实运行状态、当前活动与最近同步时间，不能退化成依赖手动刷新的静态快照；新内容默认跟随到底部，用户向上阅读历史时暂停跟随并提供“回到最新”。*原因：运行中的 Codex 任务需要持续反馈，同时不能打断用户阅读旧内容。*
- **2026-08-05** — 运行中的远程会话必须有持续、明确且固定可见的进行态动画；长消息按标题、段落、列表和代码等语义排版，不能直接显示难读的原始 Markdown。*原因：用户需要在等待时确认任务仍在推进，并能长时间阅读同步记录。*
- **2026-08-05** - 项目控制台、会话监控和远程会话必须复用同一侧栏组件与样式源；页面切换只改变当前导航项，主题开关的尺寸、字号、位置和图标中心不可变化。*原因：跨工作区导航需要保持空间记忆，重复实现会产生覆盖冲突和视觉跳变。*
- **2026-08-06** - 手机 PMA 是远程会话的一级使用界面，不是桌面布局的缩小版；配对属于可恢复、可持久化的配置流程，完成后应直接进入会话，只有服务端明确返回授权失效才重新配对。短暂网络波动不得立即显示断开或把用户送回配对页。*原因：移动网络天然会抖动，连接状态与设备授权是两套独立状态，不能互相覆盖。*
- **2026-08-07** - 远程会话 PWA 是独立的移动优先对话客户端，项目工作台只保留入口；会话列表使用覆盖式抽屉，切换时不得推动或重排顶部会话标题、消息区和底部输入框。*原因：手机 PWA 不是桌面工作台的缩小版，选择会话不能让核心输入区域移出屏幕。*
- **2026-08-08** - 桌面端远程会话侧栏只改变自身可见性与主内容起点，不得重置、覆盖或停用当前会话工作区；会话状态必须同时使用图标和文字，运行态使用持续旋转指示。*原因：侧栏属于导航工具，展开和收起不能中断阅读、输入或会话状态，状态也不能只依赖颜色表达。*
- **2026-08-08** - 远程会话列表必须在用户点开会话前就根据真实最新 turn 显示完成、运行、失败或中断状态；状态详情暂时不可读时显示“状态未知”，不得猜测为“已停止”。*原因：点击行为只能切换内容，不能成为纠正状态的隐式数据加载步骤。*
